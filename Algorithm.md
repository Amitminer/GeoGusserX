# GeoGusserX Location Generation Algorithm

This document provides a technical specification of the client-side location generation algorithm used in GeoGusserX to produce random, geographically distributed, and valid coordinates for gameplay.

## 1. Random Number Generation

To ensure unpredictability and prevent pattern recognition, the algorithm utilizes the Web Crypto API when available, falling back to `Math.random()` in environments where the API is not defined:

```typescript
function secureRandom(): number {
  if (typeof crypto !== 'undefined' && crypto.getRandomValues) {
    const array = new Uint32Array(1);
    crypto.getRandomValues(array);
    return array[0] / (0xFFFFFFFF + 1);
  }
  return Math.random();
}
```

## 2. Region Indexing & Selection

The region manager indexes `regions.json` (containing 5,297 global regions) using standard memory structures optimized for speed and lookup time:

- **Direct Lookups (Hash Maps)**: Countries, region types, and continents are indexed inside standard ES6 `Map` structures to support $O(1)$ filtering.
- **Fuzzy Search**: Implements Fuse.js for typo-tolerant country lookup fallback (e.g., matching partial inputs or common typing mistakes).
- **Weighted Selection**: Every region has a weight proportional to its size and geographic relevance. Regions are chosen via binary search on a cumulative weight array in $O(\log n)$ time.

## 3. Coordinate Generation Mathematics

Once a geographic region is selected, a location (comprising latitude and longitude) is generated by offset calculation from the region center.

### Geographic Offsets
Since the Earth is approximately spherical, the longitudinal degrees shrink as latitude approaches the poles. The offsets are computed using the following formulas:

$$\Delta \text{lat} = \frac{d \cdot \cos(\theta)}{111}$$
$$\Delta \text{lng} = \frac{d \cdot \sin(\theta)}{111 \cdot \cos(\text{lat}_{\text{center}} \cdot \frac{\pi}{180})}$$

Where:
- $d$ is the generated offset distance in kilometers.
- $\theta$ is the random angle in radians.
- $111$ is the approximate distance in kilometers per degree of latitude.
- $\cos(\text{lat}_{\text{center}} \cdot \frac{\pi}{180})$ adjusts the longitudinal degrees based on distance from the equator.

### Distribution Strategies
The distance $d$ and angle $\theta$ are determined by one of five distribution strategies:

1. **Uniform**:
   - Points are distributed evenly across the circular area.
   - Distance calculation uses a square root transformation to avoid concentration near the center:
     $$d = \sqrt{R} \cdot \text{radius}$$ (where $R \in [0,1)$ is a random value).

2. **Edge-Biased**:
   - Skews locations toward the boundary of the region.
   - Leverages a custom shape parameter to shift random values closer to $1.0$.

3. **Center-Biased**:
   - Concentrates locations near the center of the region.
   - Leverages a shape parameter to shift random values closer to $0.0$.

4. **Clustered**:
   - Groups generated coordinates into clustered nodes, simulating density distributions (such as population centers).

5. **Scattered**:
   - Evaluates multiple candidate coordinates and selects the one maximizing geographic dispersion.

## 4. Validation and Retry Flow

To guarantee coordinate validity before presenting it to the user, the algorithm verifies that:
- Latitude lies in $[-90, 90]$.
- Longitude lies in $[-180, 180]$.
- The coordinates are finite numbers (not `NaN` or `Infinity`).
- The coordinates do not equal `(0, 0)` (standard uninitialized/error coordinates).

If validation fails, the algorithm retries with a modified strategy or falls back to a predefined anchor coordinate for the region.
